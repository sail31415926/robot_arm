# 仿真使用说明（Gazebo / MuJoCo）

先在仿真里把整条链路跑通，再上实机。仿真与实机的差异见
[实机能力限制说明.md](实机能力限制说明.md)——**别把仿真里的跟踪质量外推到实机**。

---

## 0. 编译

```bash
cd ~/E7009_ws
source /opt/ros/humble/setup.bash
source .venv/bin/activate                      # 工作空间根目录的 venv
colcon build --symlink-install --packages-select robot_arm_teach
source install/setup.bash                      # ★ 新包必须重新 source，否则 launch 报 package not found
```

跑单元测试（只测纯逻辑层，不需要起任何节点）：

```bash
colcon test --packages-select robot_arm_teach
colcon test-result --verbose
```

## 1. 启动：两条命令，别叠栈

示教节点**只启动自己**。它依赖的 `ros2_control` / `arm_controller` /
`mode_manager_node` / `arm_commander` / `robot_state_publisher` 全部由既有 bringup 提供，
在示教 launch 里重复拉起会双重驱动。

```bash
# 终端① 整机栈（Gazebo）
ros2 launch robot_arm_bringup bringup.launch.py backend:=gazebo controller:=commander

# 终端② 示教节点（加 gui:=true 连操作面板一起起）
ros2 launch robot_arm_teach teach.launch.py gui:=true
```

下面 §2 的每一步都能在面板上点完（分区与流程一一对应），命令行那套仍然有效，
两者可以混用 —— 面板只是服务的客户端，状态经 latched `/robot_arm/teach/state` 同步，
所以命令行改了状态面板会立刻跟上。面板细节见 [../README.md](../README.md) 的「操作面板」一节。

⚠️ VMware 虚拟机里 Gazebo / RViz 可能崩在 `context mismatch in svga_surface_destroy`
（gzclient 退出）或 `exit code -11`（rviz2 SIGSEGV）—— 那是 `vmwgfx` 的 OpenGL 上下文
问题，不是本包的错。启动前强制软件渲染即可：

```bash
export LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe QT_X11_NO_MITSHM=1
```

代价是 `llvmpipe` 走 CPU 渲染、Gazebo 帧率明显下降；但物理仿真与 ROS 通信不受影响，
示教的时序判断走 `steady_clock`，与渲染帧率无关。

MuJoCo 后端把 `backend:=mujoco` 即可（MuJoCo 不发 `/clock`，本节点也不读它——
所有间隔判断走 `steady_clock`）。

⚠️ **确认只有一套栈在跑**。`pkill -x arm_commander_node` 杀不掉它（进程名被截断成
`arm_commander_n`，`-x` 精确匹配静默失败），用 `pgrep -af` 按完整 cmdline 查：

```bash
ps -eo pid,args | grep E7009_ws/install
```

### 启动后自检

```bash
ros2 node list | grep arm_teach
ros2 topic echo /robot_arm/teach/state --once      # latched，随时能拿到当前状态
ros2 param get /arm_teach playback.max_joint_velocity
```

`ros2 param get` 拿不到值 → YAML 顶层键写错了（必须是节点名 `arm_teach`，
不是可执行文件名 `arm_teach_node`）。写错**不报错、参数静默不生效**。

启动日志会打印一段能力摘要，其中这两行值得先看一眼：

```
点动  中继开  50Hz  限速 0.40rad/s  断流 300ms   ★ 只能动 J1-3（产品总线固定 3 轴）
手拖示教 已禁用（实机无 effort_controller，见 doc/实机能力限制说明.md）
```

## 2. 完整流程：录一条 DOLLY，回放

### ① 开始录制

```bash
ros2 service call /robot_arm/teach/start_teach robot_arm_teach/srv/StartTeach \
  "{name: 'sim_dolly_01', motion_type: {value: 1}, teach_mode: 0, description: '仿真推镜'}"
```

`motion_type.value`：0=FREEFORM 1=DOLLY 2=TRUCK 3=ARC 4=CRANE。
`teach_mode`：0=JOG（点动）1=DRAG（手拖，见下文 §4）。

节点会依次：查空闲 → 查急停/故障 → 经 `/robot_arm/switch_control_mode`
切到 `JOINT_VELOCITY` → 起 50Hz 采样器 → 打开点动闸。

### ② 点动把机械臂开起来

往示教侧的输入话题发 3 轴角速度（**只有 3 个值**，对应 Joint1-3）：

```bash
# J1 以 0.15 rad/s 正转；必须持续发布，停发即停（断流看门狗 0.3s）
ros2 topic pub -r 20 /robot_arm/teach/jog robot_arm_teach/msg/JogCommand \
  "{velocities: [0.15, 0.0, 0.0]}"
```

Ctrl-C 停掉这条命令 → 中继补一帧全 0 → 机械臂原地停住。

看录了多少点：

```bash
ros2 topic echo /robot_arm/teach/state
# state: 1 (RECORDING)   point_count: 137   elapsed_sec: 5.42   jog_relay_enabled: true
```

中途暂停/继续（暂停时时间轴冻结，点动闸关，并立刻补发全 0）：

```bash
ros2 service call /robot_arm/teach/pause_teach std_srvs/srv/Trigger
ros2 service call /robot_arm/teach/resume_teach std_srvs/srv/Trigger
```

### ③ 结束录制

```bash
ros2 service call /robot_arm/teach/stop_teach robot_arm_teach/srv/StopTeach "{}"
# success: true  point_count: 156  raw_point_count: 412  duration_sec: 8.24
```

轨迹此刻只在**内存缓冲区**，没落盘。这样可以先回放看看，满意再存。
`raw_point_count` 与 `point_count` 的差就是位置阈值压缩掉的量。

### ④ 存盘（可顺手补运镜元数据）

```bash
ros2 service call /robot_arm/teach/save_trajectory robot_arm_teach/srv/SaveTrajectory \
  "{name: 'sim_dolly_01', overwrite: true,
    meta_override: true,
    motion_meta: {subject_label: 'person_0',
                  dolly_direction: [1.0, 0.0, 0.0],
                  dolly_distance_m: 0.2,
                  dolly_keep_camera_facing: true}}"
# path: /home/<user>/.ros/robot_arm_teach/sim_dolly_01.yaml
```

落盘前会跑完整静态校验，不合格**拒绝写入**——磁盘上不留一条自己都通不过校验的轨迹。

### ⑤ 回放

先干跑一遍（只校验，不下发任何指令）：

```bash
ros2 service call /robot_arm/teach/play_trajectory robot_arm_teach/srv/PlayTrajectory \
  "{name: 'sim_dolly_01', dry_run: true}"
# exit_reason: dry_run_ok
```

真回放（半速）：

```bash
ros2 service call /robot_arm/teach/play_trajectory robot_arm_teach/srv/PlayTrajectory \
  "{name: 'sim_dolly_01', speed_scale: 0.5, loop_count: 1}"
```

进度反馈：

```bash
ros2 topic echo /robot_arm/teach/playback
# status: 0  point_index: 88  point_total: 156  progress_percent: 56.4  speed_scale: 0.5
```

暂停 / 继续 / 停止 / 中途变速：

```bash
ros2 service call /robot_arm/teach/pause_playback  std_srvs/srv/Trigger
ros2 service call /robot_arm/teach/resume_playback std_srvs/srv/Trigger
ros2 service call /robot_arm/teach/stop_playback   std_srvs/srv/Trigger
ros2 service call /robot_arm/teach/set_playback_speed \
  robot_arm_teach/srv/SetPlaybackSpeed "{speed_scale: 0.3}"
```

暂停会**下发一条「保持在当前实测位置」的轨迹**，不是发空轨迹——
空轨迹不会让 JTC 停下，它会把手上那条剩下的部分继续执行完。

变速在**当前分段走完后**生效（约 `playback.chunk_horizon_sec`）。要立刻生效就
先 pause 再改再 resume。

### ⑥ 列出 / 删除

```bash
ros2 service call /robot_arm/teach/list_trajectories \
  robot_arm_teach/srv/ListTrajectories "{filter_by_motion_type: false}"
# 只列 ARC：{filter_by_motion_type: true, motion_type_filter: 3}

ros2 service call /robot_arm/teach/delete_trajectory \
  robot_arm_teach/srv/DeleteTrajectory "{name: 'sim_dolly_01'}"
```

## 3. 仿真里能验、实机上不一样的东西

| 现象 | 仿真 | 实机 |
| --- | --- | --- |
| 位置跟踪 | Gazebo 的位置接口是 `SetPosition`（运动学瞬移），实际位置**恒等于**设定点，跟踪"完美" | 有位置环滞后与静差，回放轨迹会被平滑、幅度略小 |
| 点动手感 | 平顺 | 单点轨迹 + 每周期重规划的固有纹波（robot_arm/CLAUDE.md 实测 J1@0.15rad/s 跟踪率仅 71%~74%） |
| 重力 | Gazebo 关节无摩擦；失能不会"砸" | 失能会让 J2/J3 失去支撑、机械臂下沉 |
| 云台 J4-6 | 跟着 JTC 动 | 跨机 DDS，板端未上电就没有回读（`/joint_states` 缺轴 → 采样暂停并告警） |

所以：**仿真验的是逻辑与接口，不是手感和精度。**

## 4. 仿真里试手拖示教（可选，实机不可用）

`JOINT_EFFORT` 已于 2026-08-11 在 Gazebo 开通（`arm_effort_controller` + URDF effort
接口 + pinocchio 重力补偿）。仿真里可以打开手拖示教：

```bash
ros2 launch robot_arm_teach teach.launch.py allow_drag:=true
ros2 service call /robot_arm/teach/start_teach robot_arm_teach/srv/StartTeach \
  "{name: 'sim_drag_01', motion_type: {value: 0}, teach_mode: 1}"
```

三件必须知道的事：

1. **重力补偿不是本节点做的**，是 `mode_manager_node` 的 effort 节拍
   （`effort_rate_hz` 默认 100Hz，下发 `g(q) + 用户增量 − d·q̇`）。
   本节点在手拖模式下**一个力矩指令都不发**——需要的增量恰好是 0，
   而**绝不能**发字面 0 力矩：力矩模式下 0 不是「停」而是「自由下垂」
   （实测切进力矩模式后 J2 从 +0.500 直接砸到下限 -0.981）。
2. 先确认 `ros2 param get /mode_manager_node gravity_compensation` 是 `true`。
   是 `false` 就别进这个模式。
3. 纯重力补偿无耗散，Gazebo 里仍有约 0.01 rad/s 的单向漂移，
   录出来的轨迹会带这点漂移。要彻底锁住得加位置弹簧项，那已经是阻抗控制。

实机上 `allow_drag:=true` 也没用——`real.launch.py` 故意不配 `effort_controller`，
ModeManager 会明确拒绝切换。详见[实机能力限制说明.md](实机能力限制说明.md)。

## 5. 排查

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| `start_teach` 返回「未收到 /robot_arm/arm_status」 | `arm_commander` 没跑 | 用 `controller:=commander` 起 bringup；或确认机械臂正常后设 `safety.require_arm_status:=false` |
| `start_teach` 返回「控制模式服务不可用」 | `mode_manager_node` 没跑 | 同上，`controller:=commander` 会拉起它 |
| 状态一直 RECORDING 但 `point_count` 不涨 | 6 轴回读不全，采样暂停 | `ros2 topic echo /joint_states --once` 看少了哪几个轴；云台 J4-6 缺就是跨机 DDS/板端未上电 |
| 点动发了但机械臂不动 | 不在 RECORDING 态（闸关着），或指令长度不是 3 | 看 `/robot_arm/teach/state` 的 `jog_relay_enabled`；长度不对时 `VelocityStreamServer` 会刷「关节速度指令长度 N ≠ 3，已丢弃」 |
| 回放报 `not_at_start` | 当前位置离轨迹起点太远且 `auto_approach:=false` | 设 `playback.auto_approach:=true`，或先手动/用 `MoveToJoint` 走到起点 |
| 回放报 `over_speed` | 录制时速度超过 `playback.max_joint_velocity` | 降 `speed_scale`（降速会按 ×s / ×s² 重新判），或调高上限（先确认 URDF 机械限） |
| 回放报 `collision` | 抽样点被 `/check_state_validity` 判 invalid | 多半是手改过的 YAML 或跨机器复用的轨迹；`move_group` 没跑时这道闸会 fail-open 并告警 |
| 回放中断「底层控制模式已被切离 TRAJECTORY」 | 别的应用抢了速度总线 | 确认没有第二个上层节点在切模式 |
| 保存报「同名轨迹已存在」 | 未传 `overwrite` | `overwrite: true` |

日志一律落 `~/.ros/log/<run>/`。想看更细：`teach.launch.py log_level:=debug`。
