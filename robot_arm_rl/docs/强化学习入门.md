# 强化学习入门 — 以 robot_arm_rl 为例

写给有控制背景（MPC / QP / 全身控制）的工程师。全文用本仓库
`robot_arm_rl`（MuJoCo 摄影构图跟拍 + SAC）做贯穿案例：每讲一个概念，
就指到工程里对应的代码。建议边读边开着
`src/E7009/robot_arm/robot_arm_rl/scripts/envs/emeet_arm_env.py`。

## 1. 用控制的语言理解 RL

RL 本质是**不知道模型时的数值最优控制**。你已有的概念可以直接映射：

| 最优控制 / MPC | RL 术语 | 说明 |
|---|---|---|
| 状态 x | 观测 s（observation/state） | 部分可观时二者不同，工程上常混称 |
| 控制量 u | 动作 a（action） |  |
| 代价 J（取负） | 奖励 r（reward） | RL 最大化累计奖励 = 最小化累计代价 |
| 反馈控制律 u=π(x) | 策略 π(a\|s)（policy） | RL 学出来的就是一个神经网络控制器 |
| cost-to-go V(x) | 值函数 V(s) / Q(s,a) | Q = 在 s 做 a 后按 π 走到底的期望回报 |
| 折扣/时域 | 折扣因子 γ ∈ (0,1) | γ=0.99 ≈ 有效时域 1/(1-γ)=100 步 |
| 系统模型 f(x,u) | 环境 env.step() | model-free RL 不需要显式模型，只需能采样 |
| 滚动优化（每周期重解） | 训练期离线优化 | 部署时只做一次网络前向（微秒级） |

核心区别一句话：**MPC 把优化放在线上每个控制周期；RL 把优化搬到训练期，
用上百万次仿真交互"预先解好"一个全局反馈律**。代价是训练贵、没有硬约束
保证；收益是在线计算极小、能吃进解析建模困难的目标（比如"画面构图好看"）。

什么时候该用 RL（本项目的判据）：目标写不成干净的解析代价（构图美学）、
存在需要预判的随机扰动（主体运动）、多目标权衡规则说不清（精度 vs 平滑）。
反之，能用 IK/MPC 三行解掉的事不要用 RL——本项目旧版环境就是教训
（见 §6.1）。

## 2. 形式化：MDP 五元组

马尔可夫决策过程 (S, A, P, R, γ)：状态集、动作集、转移概率 P(s'|s,a)、
奖励函数 R(s,a)、折扣因子。目标是找策略 π 最大化期望回报：

    J(π) = E[ Σₜ γᵗ · r(sₜ, aₜ) ]

两个派生量是几乎所有算法的地基：

- **状态值** V^π(s) = 从 s 出发按 π 走的期望回报；
- **动作值** Q^π(s,a) = 在 s 先做 a、之后按 π 走的期望回报。

它们满足**贝尔曼方程**（动态规划的递推式，你在 DP/LQR 里见过同款结构）：

    Q^π(s,a) = E[ r + γ · Q^π(s', a') ],  a' ~ π(·|s')

RL 算法几乎都是在"用采样近似解贝尔曼方程"。对应到工程：`env.step()`
返回的 `(obs, reward, terminated, truncated)` 就是一次贝尔曼方程的采样。

`terminated` vs `truncated` 的区别值得记住：terminated = 任务本身结束
（本项目：丢失主体 1 秒），回报到此为止；truncated = 人为截断
（跑满 500 步），bootstrap 时还要加上 V(s_final)。SB3 会自动区分处理，
但你设计环境时标错这两个字段会造成隐蔽的值函数偏差。

## 3. 算法地图：从值迭代到 SAC

只需要建立脉络，不需要每个都会推：

```
动态规划(已知模型)
 └─ Q-learning：采样逼近贝尔曼最优方程（表格）
     └─ DQN (2015)：Q 用神经网络 + 经验回放 + 目标网络 → 只能离散动作
         └─ DDPG：加一个确定性 actor 网络输出连续动作
             └─ TD3：双 Q 网络治 Q 值高估 + 目标平滑
             └─ SAC (2018)：随机策略 + 最大熵目标 ← 本项目用这个
另一条线（策略梯度）：
 REINFORCE → A2C → TRPO → PPO (2017)：直接对 J(π) 做梯度上升，on-policy
```

机器人连续控制圈实际就两个默认选项：

| | SAC | PPO |
|---|---|---|
| 数据利用 | off-policy，经验回放，样本效率高 | on-policy，采完就扔，样本效率低 |
| 适用 | 仿真步进贵（本项目：每步要跑 IK+物理） | 仿真极快可大规模并行（Isaac Gym 上万环境） |
| 稳定性 | 对超参较鲁棒（自动温度） | 对奖励尺度/超参较敏感，但大并行下很稳 |

**SAC 三个关键机制**（对照 `train_sac.py` 的 `SAC_KWARGS`）：

1. **最大熵目标**：J = Σ E[r + α·H(π(·|s))]，在回报上加策略熵。效果是
   "在不损失回报的前提下尽量随机"——探索内建于目标而非外挂噪声。
   `ent_coef='auto'` 表示温度 α 自动调节（对偶梯度法把熵约束在目标值附近），
   这是 SAC 对超参鲁棒的主要来源。
2. **双 Q 网络取 min**：两个独立 critic，目标值取较小者，抑制 Q 高估
   （高估是 bootstrap + max 操作的系统性 bias，DDPG 时代的头号死因）。
3. **经验回放 + 目标网络软更新**：`buffer_size=1e6` 存历史转移随机抽 batch
   （打破样本相关性）；`tau=0.005` 是目标网络的低通滤波系数——
   和你熟悉的一阶惯性滤波完全同构，为 bootstrap 目标提供慢变基准。

其余超参速查（对照代码）：`learning_rate=3e-4`（Adam 标配）、
`batch_size=1024`、`gradient_steps=4`（每采 1 步做 4 次梯度更新，
GPU 快时可加大）、`learning_starts=10000`（先攒 1 万步纯随机数据再开始更新，
保证回放池里有多样性）、`net_arch=[512,512]`（actor/critic 均为两层 MLP）。

## 4. 环境设计学（RL 工程 80% 的功夫在这）

算法是现成的（SB3 一行），**真正决定成败的是环境定义**：动作空间、
观测空间、奖励、重置分布、终止条件。本项目每一处设计都有对应的坑。

### 4.1 动作空间：让 RL 只做该 RL 做的事

本项目动作是 5 维增量 `[Δθ, Δφ, Δr, Δpan, Δtilt]`，而不是 6 个关节角：

- **分层**：解析 look-at + IK 负责"关节怎么转"，RL 只决策"镜头怎么运"。
  搜索空间从 6 维关节位形坍缩到任务语义空间，样本效率高一个量级。
  这与全身控制里"任务空间 → 关节空间"的分层是同一哲学。
- **增量式**（Δ 而非绝对值）：天然限制每步变化率（等效执行器速率约束）、
  策略输出以 0 为中心（网络好学）、平滑性可以通过惩罚 Δ 的变化率来塑造。
- **归一化 [-1,1]**：所有维度同尺度，`DTHETA_MAX` 等常数负责换算物理量。
  神经网络对输入输出的尺度极其敏感，这是铁律。

### 4.2 观测空间：够用、归一、无歧义

原则：**策略需要知道的信息一个不少（马尔可夫性），且全部归一到 O(1)**。
对照 `_get_obs()` 逐条看设计动机：

- `sin(θ), cos(θ)`：角度直接进网络在 ±π 处不连续，拆正余弦是标准做法；
- `prev_action`：让策略感知自己上一步做了什么——配合抖动惩罚才学得出平滑；
- 构图误差 `u-u*, v-v*` 和目标 `u*, v*, s*` **同时给**：误差驱动控制，
  目标提供上下文（goal-conditioned，见 4.5）；
- 图像速度 `du, dv`：主体在动，不给速度就破坏马尔可夫性
  （同一个画面位置，主体往左走和往右走需要不同动作）；
- 关节位置/速度：让策略感知限位与动力学状态。

### 4.3 奖励设计：多目标加权 + 防爆炸

`_compute_reward()` 六项，就是你写 MPC 代价函数的直觉，外加两条 RL 特有纪律：

| 项 | 表达式要点 | 对应 MPC 里的 |
|---|---|---|
| 构图 | -8·min(‖uv误差‖², 4.5) | 跟踪误差项 |
| 可见性 | 画面内 +1 / 画面外 -5 | 硬约束的软化（屏障函数） |
| 尺寸 | -0.5·clip(s误差,±3)² | 第二个跟踪项 |
| 平滑 | -0.2·‖a‖² | 控制能量项 R·u² |
| 抖动 | -0.5·‖a-a_prev‖² | Δu 惩罚（rate penalty） |
| 限位余量 | 边界 0.1rad 内二次惩罚 | 状态约束的软化 |

两条纪律：

1. **每一项都截断**（min/clip）。主体飞出画面时误差可以任意大，一个
   outlier 奖励会毁掉值函数学习——这是新手最常见的训崩原因。
2. **各项量级要平衡**。某项常态下比其他项大一个数量级，策略就只优化它。
   验证方法：随机策略跑几百步，把六项分别打印出来看分布（练习 8.3）。

另一个经典陷阱是**奖励黑客（reward hacking）**：策略钻奖励函数的空子
而不是完成你心里想的任务。防它的唯一办法是可视化看行为，不要只看曲线。

### 4.4 重置分布与终止

- **reset 决定训练数据的覆盖面**：主体位置、起始球坐标、构图目标、主体
  速度全部随机化——这既是 domain randomization 的雏形，也直接决定策略
  的泛化边界（`sim_to_sim_test.py` 专门测这个边界外的表现）。
- **reset 必须只产出有效状态**：本环境用"几何预筛 + IK 到位校验"的拒绝
  采样。曾经的 bug：随机出超臂展的目标 → IK 残差几百 mm → episode 从
  第一帧就是坏样本，策略无论怎么做都拿大额负奖励，学习信号全是噪声。
- **提前终止是学习信号也是算力优化**：丢失主体 1s 即终止 + 罚分，
  策略会学到"别丢"；同时坏 episode 不再浪费 400 步采样预算。

### 4.5 goal-conditioned：一个策略服务一族任务

把目标 (u\*, v\*, s\*) 放进观测并在训练时随机采样，得到的是
**以目标为条件的策略族** π(a|s, g)——部署时改参数即可切换构图，
不用重训。这是通往"GUI 下发任意构图"的正确形态。代价是任务分布更宽、
需要更多样本，评估时必须**固定目标**才能跨训练比较（`train_sac.py`
的评估环境固定 DEFAULT_GOAL 就是为此）。

## 5. 训练工程实践

### 5.1 VecNormalize：观测/奖励在线归一化

`VecNormalize` 维护观测各维的运行均值/方差，实时白化。**统计量是模型的
一部分**：保存/加载模型必须连同 `vec_normalize_*.pkl`，部署时用同一份
统计量做 `normalize_obs`，否则观测分布错位、策略直接失效。
（本仓曾有 resume 时统计量没真正生效的 bug，已修——`train_sac.py`
里"先换 VecNormalize 再 load 模型"的顺序就是修复。）

### 5.2 并行采样

`SubprocVecEnv` 开 N 个进程各跑一个环境。SAC 是 off-policy，并行的
收益主要是**墙钟时间**而非算法性质。经验：CPU 训练时 n_envs=4~8；
瓶颈在 GPU 梯度步时加大 `gradient_steps` 而不是环境数。

### 5.3 训练曲线怎么看（tensorboard --logdir logs/tb）

| 曲线 | 健康形态 | 病症 |
|---|---|---|
| `rollout/ep_rew_mean` | 先平（随机填充期）后爬升、渐进平台 | 一直平：奖励无梯度信号或尺度失衡；爬了又崩：lr 过大 / 值函数发散 |
| `rollout/ep_len_mean` | 本项目应爬向 500（不再提前丢失） | 贴地：一直触发提前终止，任务过难或起始分布太苛刻 |
| `train/critic_loss` | 有波动但有界 | 持续上涨发散：奖励 outlier / lr 过大 |
| `train/ent_coef` | 从初值缓慢下降后稳住 | 掉到 ~0：策略过早确定化，探索死了 |
| `eval/mean_reward` | 阶梯式上升 | 与 rollout 差距巨大：过拟合训练分布 |

诊断顺序永远是：**先怀疑环境（奖励/观测/重置），再怀疑超参，最后才怀疑算法**。

### 5.4 评估纪律

- 评估用 `deterministic=True`（取策略均值，不采样）；
- 固定构图目标 + 固定条件，否则轮间方差淹没进步；
- 除了奖励，看**任务指标**：构图误差（0=命中）、可见率、轮长
  （`eval_policy.py` 全都打出来了）；
- 最终结论要跑 `sim_to_sim_test.py`：分布内好不算好，分布外崩不崩才见真章。

## 6. 本项目案例研究：三个真实 bug 的教训

这三个 bug 都在 2026-08-19 整理时修复，原始现场记录在环境源码注释里。
它们分别对应 RL 落地的三类经典失败模式，比任何教材例子都真实：

### 6.1 任务被解析捷径掏空（旧版任务定义缺陷）

旧环境里相机朝向由 look-at 解析给出且**无偏置维度** → 主体恒在画面中心
→ 构图目标 v\*=0.67 原理上不可达（恒定误差项，策略无法影响），
策略实际只学会了"调半径凑尺寸"。**教训：设计任务前先问——策略的动作
真的能影响奖励的每一项吗？有没有解析法三行就能替代的捷径？**
新版加入 Δpan/Δtilt 后，构图落点成为策略真正可控的量（验证脚本显示
恒定 tilt 动作可把 v 从 0.50 推到 0.670）。

### 6.2 仿真保真度被静默破坏（IK 污染物理状态）

`_ik_solve` 迭代时借 `data.qpos` 做正运动学，**忘了还原** → 每步物理
状态被 IK 解覆盖 = 机械臂瞬移，PD 跟踪动力学完全被绕过。策略在"假动力学"
里训练，观测里的速度、平滑奖励全部失真，sim2real 差距被系统性低估。
**教训：环境里任何"借用仿真状态做计算"的代码（IK、碰撞检查、渲染）
都必须快照/还原；验证方法是给大幅动作、检查物理状态是否滞后于指令**
（真实跟踪必有残差，瞬移没有）。

### 6.3 观测通道从未工作（相机帧错挂）

IK 目标挂在 tool0 的 site 上（只含 J1-3），相机却在云台链末端 Cam0
（J4-6 之后），且投影用了错误的轴约定（MuJoCo 相机帧看 -Z，代码按 +Z 算）
→ 云台从未被控制、主体从未真正出现在画面里，可见率 0%。训练曲线看起来
"在学"（策略在优化它能影响的残渣项），掩盖了根本性断裂。
**教训：环境写完先跑"白痴基线"——零动作、随机动作、手写 P 控制器各
跑一遍，打印任务指标。零动作下主体都看不见，说明闭环根本没接上；
这 10 分钟的检查能省掉几周的无效训练。**

## 7. Sim2Real 路线（本项目的下一站）

1. **域随机化**：物理参数（增益、延迟、摩擦）、感知噪声（检测框抖动、
   丢帧）、几何（主体大小）逐项加扰动，逼策略学到鲁棒不变量；
2. **观测对齐**：部署侧观测的每一维必须与训练分布同源同尺度——
   当前部署骨架的已知欠账：qvel 填零、投影用几何占位而非真实检测框、
   策略频率 10↔50Hz 不一致（`rl_policy_node.py` 文件头如实列着）;
3. **sim-to-sim 先行**：跨到另一个仿真器（Gazebo）验证，比直接上实机
   便宜一个量级；`sim_to_sim_test.py` 的分布外测试是第一道关；
4. **实机上的安全壳**：RL 输出永远过一层限幅/限速/工作空间检查再进
   总线（本仓已有 ModeManager 仲裁与看门狗体系可复用）。

## 8. 动手练习（按序做，每个都有明确验收）

1. **跑通管线**：30k 步冒烟训练 + tensorboard 看曲线 + eval_policy 可视化。
   验收：能指着每条曲线说出它是什么。
2. **白痴基线**：零动作、随机动作各跑 20 轮，记录构图误差/可见率，
   作为策略的对照底线。验收：知道"策略至少要打败谁"。
3. **奖励解剖**：改 `_compute_reward` 让它返回 dict 打印各项分布。
   验收：说出哪两项量级最大、为什么。
4. **消融实验**：去掉观测里的 `du,dv` 重训，对比运动主体评估的可见率。
   验收：亲眼看到破坏马尔可夫性的后果。
5. **奖励改造**：把平滑惩罚加倍/清零各训一次，对比 eval 构图误差与
   动作方差。验收：理解精度-平滑的帕累托权衡。
6. **超参实验**：lr=3e-3 训一次看崩溃形态；`ent_coef` 固定 0.001 看
   过早收敛。验收：见过两种最常见的病。
7. **泛化压测**：训完跑 sim_to_sim_test，找出最崩的条件，把该条件
   加进训练随机化再训，验证是否补上。验收：完成一轮"评估→发现→修复"闭环。
8. **（进阶）换算法**：用 SB3 的 PPO 跑同一环境，对比样本效率与墙钟
   时间。验收：能给"这个任务该用 SAC 还是 PPO"一个有数据的回答。
